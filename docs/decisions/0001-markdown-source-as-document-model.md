# ADR 0001：以 Markdown 原文作為文件模型

**狀態：已採納，尚未實作。**

## 背景

GPUI Editor 要讓使用者直接編輯排版後的內容，同時保留原本的 `.md` 檔案。同樣的畫面可能來自不同的 Markdown 寫法，例如 `__粗體__` 和 `**粗體**`。[PRD](../prd/gpui-editor.md#需求與驗收條件提案) 要求未編輯的原文逐字保留；僅能重現相同畫面不夠。第一版不支援的語法也不能在儲存時被無聲移除或改寫。

## 考慮過的方案

1. **以 Markdown 原文為準。** 從原文解析出畫面需要的結構，讓畫面上的編輯對應到原文範圍。可以保留未變更的語法，但須維護畫面與原文的對應。
2. **以富文字模型為準，存檔時產生 Markdown。** 直接操作文字及其格式較自然，但模型若只記錄「這段是粗體」，就無法還原原檔用的是 `__` 還是 `**`。要符合保留要求，還得額外追蹤原始寫法與不支援的內容。

## 決策

採用方案 1。**目前編輯中的 Markdown 原文是文件內容的唯一依據。** 解析結構和渲染結果都由原文衍生，不各自保存一份可獨立變更的文件。使用者編輯文字、格式或區塊時，更新對應的原文範圍；存檔不從渲染結果重建整份文件。若無法保留原文中的不支援內容，不覆寫原檔。

### 影響

- 未編輯的 Markdown 寫法、空格與不支援的內容可原樣保留；例如只改標題，不會改寫 GFM 表格。
- 編輯器要維護畫面選取範圍與原文位置的對應。跨段落編輯，以及 front matter、Mermaid、LaTeX 在原文與渲染結果之間切換，都是需要驗證的情境。
- 本決策不指定 Markdown 解析器、文字緩衝區的資料結構或渲染函式庫。

### 驗證方式

使用 [PRD 的共用驗收案例](../prd/gpui-editor.md#共用驗收案例)。只改標題並存檔，比對前後檔案，確認差異只在標題一行，front matter 與表格的空格和原文都沒變。再就地修改一個 LaTeX 公式，存檔重開後確認修改後的語法仍在，且公式正確顯示。
