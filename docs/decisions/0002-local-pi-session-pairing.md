# ADR 0002：透過本機配對將編輯器回饋交給 Pi

**狀態：提案。**

## 背景

Developer Mode 要讓使用者指出 GPUI Editor 的介面元件，附上文字或圖片，將回饋送進正在使用的 Pi session。Pi 也需要能讀取近期的編輯器診斷紀錄。關鍵不是箭靶放在哪裡，而是**哪個程序有權傳送或讀取哪些資料，以及何時撤銷這個權限**。

目前編輯器獨立處理視窗、文件與儲存；Pi 則管理自己的 session、模型與工具。整合不應另開一個 agent，或讓編輯器持有模型憑證及執行指令。

## 考慮過的方案

1. **Pi extension 與編輯器透過 Unix domain socket 配對。** 保留兩個獨立程序，使用檔案系統權限限制可連線的 OS 帳號，不需開 TCP port；代價是須處理本機實例探索、連線生命週期及殘留端點。
2. **透過 localhost HTTP 配對。** 可使用通用 HTTP 工具測試，但仍需處理端點探索、驗證及生命週期。只綁定 loopback 並不能限制到特定 OS 帳號；首版也不需要讓瀏覽器或其他 HTTP client 連入。
3. **由編輯器啟動並管理 Pi。** 編輯器可以控制 session 的啟停，但會接手 Pi 的安裝、模型與工具設定，且無法直接保留使用者目前開著的 session。這不符合把回饋送到既有 session 的目標。

## 決策

提議採用方案 1。**GPUI Editor 管理使用者同意與資料範圍；Pi extension 負責把回饋交給當前 session。**

- **配對**：Developer Mode 預設關閉，只有開啟時才在使用者專屬的暫存目錄建立 Unix domain socket。從可信專案載入的 Pi extension 可提出配對要求，但必須由使用者在編輯器確認，才可收取回饋或讀取診斷。每個編輯器實例同時只配對一個 session。解除配對、關閉模式、斷線或 Pi session 更換時，撤銷存取，不自動重連。本機配對不防護同一 OS 帳號下的惡意程序。
- **回饋**：元件資料限於 app 明確標記的 ID、靜態名稱及位置，不自動附上文件文字、檔名或連結。只有使用者按 **Send to Pi** 才傳送文字和預覽過的附件。主動截圖只擷取編輯器視窗，不能擷取時可貼圖或只送文字。Extension 將回饋當成一般 user message，不展開 slash command；若 session 忙碌，排到目前工作之後。回執只表示 extension 已接手，不代表模型已收到或處理。收到的內容可能存入 Pi session 紀錄或送到模型服務。
- **診斷**：已配對的 session 只能透過唯讀 tool 查詢 Developer Mode 開啟期間、有限筆數的結構化 app 事件。不得提供任意檔案、系統 log、Markdown 原文或憑證。關閉模式會停止記錄並清除暫存；不會刪除先前已送進 Pi 的內容。

### 影響

- 編輯器不需內嵌 Pi，也不會因啟用模式而自行開啟 agent 或對外連線。Pi 仍依既有 session 的模型與工具權限處理回饋；配對不是 Pi 的執行沙箱。
- 首版限於同一台 Mac、同一 OS 帳號及已配對的 session。授權與連線狀態不寫入磁碟，重新啟動或切換 session 後須重新配對。
- 原生視窗截圖所需的 macOS API 與權限仍待驗證。若無法只擷取編輯器視窗，不以整個桌面的截圖替代。

### 驗證方式

驗證拒絕配對、關閉 Developer Mode 或切換 session 後，舊連線不能再讀取診斷。用測試文件選取 **Save** 按鈕，確認不會存檔；按 **Cancel** 時 Pi 不會收到訊息，按 **Send to Pi** 後只有配對的 session 收到元件、文字及所選附件。確認截圖不包含其他視窗，診斷不含測試文件內容。
